앱을 처음 설치하고 열었는데 화면에 아무것도 없다면, 사용자는 무엇을 해야 할지 몰라요. 그대로 앱을 닫기도 해요.

이 텅 빈 화면을 **빈 화면(Empty State)**이라고 불러요. 대부분의 메이커가 화면이 데이터로 가득 찬 모습만 디자인하고, 빈 화면은 "데이터가 없습니다" 한 줄로 넘어가요. 그런데 새 사용자가 **가장 먼저** 보는 화면이 바로 여기예요.

## 빈 화면은 언제 생길까

| 상황 | 예시 |
|---|---|
| 처음 사용할 때 | 가계부 앱을 처음 열어서 기록이 하나도 없을 때 |
| 검색·필터 결과가 없을 때 | 검색어에 맞는 결과가 0개일 때 |
| 다 끝냈을 때 | 할 일을 전부 완료했을 때, 알림을 다 읽었을 때 |
| 문제가 생겼을 때 | 인터넷 연결이 끊겨 불러오지 못했을 때 |

같은 "빈 화면"이라도 상황마다 사용자에게 필요한 말이 달라요.

## 좋은 빈 화면의 3가지 원칙

UX 리서치 기관 닐슨 노먼 그룹(Nielsen Norman Group)은 빈 화면 설계 원칙을 세 가지로 정리했어요.

### 1. 지금 상태를 알려주기

화면이 비어 있는 이유를 말해주세요. **아직 불러오는 중인지, 오류가 났는지, 정말 데이터가 없는지** 사용자는 화면만 보고는 구분할 수 없어요.

| 아쉬운 예 | 나은 예 |
|---|---|
| (아무것도 없는 화면) | 아직 기록이 없어요 |
| 데이터 없음 | "고양이"에 맞는 결과가 없어요 |
| 오류 | 인터넷 연결을 확인해주세요 |

### 2. 이곳에 무엇이 생기는지 알려주기

빈 화면은 기능을 가르쳐주기 가장 좋은 순간이에요. 이 자리에 **어떤 것이 쌓이는지** 짧게 보여주세요. 예시 이미지나 한 줄 설명이면 충분해요.

> 쓴 돈을 기록하면 여기서 한 달 흐름을 볼 수 있어요.

닐슨 노먼 그룹은 앱을 처음 켰을 때 한꺼번에 보여주는 튜토리얼보다, **그 화면에 도착한 순간 보여주는 안내**가 더 효과적이라고 설명해요.

### 3. 다음 행동으로 바로 이어주기

설명만 하고 끝나면 사용자는 버튼을 찾아 헤매요. 빈 화면 안에 **바로 할 수 있는 버튼**을 두세요.

> 아직 기록이 없어요
> 쓴 돈을 기록하면 한 달 흐름을 볼 수 있어요
> **[첫 기록 남기기]**

검색 결과가 없을 때는 "검색어 다시 입력", "필터 초기화" 같은 출구를 주세요.

## 상황별로 다르게

- **처음 사용할 때**: 기능 소개 + 첫 행동 버튼. 가장 공들여야 할 화면이에요.
- **검색 결과가 없을 때**: 무엇을 검색했는지 보여주고, 철자 확인이나 필터 해제를 제안하세요.
- **다 끝냈을 때**: 칭찬해주세요. "오늘 할 일을 모두 끝냈어요" 한 줄이 기분을 바꿔요.
- **문제가 생겼을 때**: 사용자 탓처럼 들리지 않게, 무엇을 하면 되는지 알려주세요. 다시 시도 버튼은 필수예요.

## 빈 화면 체크리스트

- [ ] 앱의 모든 목록 화면에 빈 화면을 따로 디자인했다
- [ ] 불러오는 중, 오류, 데이터 없음을 서로 다르게 보여준다
- [ ] 빈 화면마다 이곳에 무엇이 생기는지 한 줄로 설명한다
- [ ] 빈 화면마다 다음 행동 버튼이 하나 있다
- [ ] 다 끝낸 상태에는 칭찬이나 다음 제안이 있다

## 마무리

빈 화면은 데이터가 없는 화면이 아니라, **사용자가 처음 만나는 화면**이에요. 가득 찬 화면을 공들여 디자인하는 만큼, 비어 있는 화면에도 한 번 더 신경 써보세요. 첫인상이 달라져요.
