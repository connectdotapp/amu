앱스토어에서 앱을 검색하면, 사람들은 설명을 읽기 전에 **스크린샷부터** 봐요. 그리고 검색 결과에서 보이는 스크린샷은 생각보다 적어요.

애플은 이렇게 안내해요. "앱 프리뷰(영상)가 없으면, 스크린샷 방향에 따라 **처음 1~3장이 검색 결과에 나타납니다.**" 즉, 사용자가 앱을 누를지 말지는 대부분 이 1~3장에서 정해져요.

> 스크린샷은 최대 10장까지 올릴 수 있지만, 승부는 처음 3장에서 나요.

## 먼저 알아둘 규격

규격은 기기가 나올 때마다 바뀌니, 제출 직전에 공식 문서를 한 번 더 확인하세요.

**App Store (iPhone)**

| 항목 | 내용 |
|---|---|
| 개수 | 최소 1장, 최대 10장 |
| 필수 사이즈 | 다이내믹 아일랜드가 있는 iPhone(중간 크기 화면) |
| 세로 크기 | 1206 × 2622 또는 1179 × 2556 픽셀 |
| 파일 형식 | JPEG, PNG |

필수 사이즈를 올리지 않으면 큰 화면용 스크린샷을 줄여서 대신 써요.

**Google Play**

| 항목 | 내용 |
|---|---|
| 개수 | 게시하려면 최소 2장 (기기 유형별 최대 8장) |
| 파일 형식 | JPEG 또는 24비트 PNG (투명도 없음) |
| 크기 | 짧은 변 320px 이상, 긴 변 3,840px 이하, 긴 변이 짧은 변의 2배를 넘지 않게 |
| 추천 영역 노출 | 1080px 이상 스크린샷 4장 이상 (세로는 최소 1080 × 1920) |

구글 플레이의 큰 추천 영역에 노출되려면 1080px 이상 스크린샷이 **4장 이상** 있어야 해요. 2장만 올리고 끝내면 이 기회를 놓쳐요.

## 처음 3장 짜는 법

애플의 권장은 단순해요. "처음 이미지들은 **앱의 핵심**을 보여주고, 그다음 장마다 **주요 장점이나 기능을 하나씩** 보여주세요."

이 원칙을 5장 구성으로 옮기면 이렇게 돼요.

| 순서 | 담을 것 | 예시 (가계부 앱) |
|---|---|---|
| 1장 | 이 앱이 뭔지 한 문장 + 대표 화면 | "쓴 돈이 한 화면에 보여요" + 메인 화면 |
| 2장 | 가장 많이 쓰는 기능 하나 | "영수증 찍으면 자동 입력" + 촬영 화면 |
| 3장 | 다른 앱과 다른 점 하나 | "카드 연동 없이도 돼요" + 수기 입력 화면 |
| 4장 | 그다음 자주 쓰는 기능 | 월별 리포트 화면 |
| 5장 | 마무리 (다크 모드, 위젯 등) | 다크 모드 화면 |

1~3장만 봐도 "무엇을 하는 앱이고, 왜 이 앱이어야 하는지"가 전달돼야 해요.

## 한 장을 만들 때 지킬 것

### 1. 한 장에 한 메시지
문구는 한 줄, 길어도 두 줄로 줄이세요. 검색 결과에서 스크린샷은 손톱만 한 크기로 보여요. 작은 글씨로 기능을 나열하면 아무것도 읽히지 않아요.

### 2. 앱 화면이 주인공
문구를 크게 넣더라도, 실제 앱 화면이 잘 보여야 해요. 사용자는 "설치하면 이런 화면을 보게 되는구나"를 확인하고 싶어 해요.

### 3. 첫 장에 가장 강한 장면
온보딩이나 로그인 화면을 첫 장에 두지 마세요. 앱을 쓰는 가장 좋은 순간을 첫 장에 두세요.

### 4. 다크 모드를 지원한다면 한 장
애플도 다크 모드를 지원한다면 그 화면을 최소 한 장 넣으라고 권해요.

### 5. 앱 프리뷰(영상)를 쓴다면 첫 몇 초에 집중
앱 프리뷰가 있으면 검색 결과에서 스크린샷보다 먼저 보이고, 소리 없이 자동 재생돼요. 처음 몇 초만 보고도 무엇인지 알 수 있게 만드세요.

## 올리기 전 체크리스트

- [ ] 처음 3장만 봐도 무엇을 하는 앱인지 알 수 있다
- [ ] 장마다 메시지가 하나다
- [ ] 문구가 휴대폰 화면에서 손톱만 한 크기로도 읽힌다
- [ ] 첫 장이 로그인·온보딩 화면이 아니다
- [ ] App Store 필수 사이즈를 올렸다
- [ ] Google Play에 1080px 이상 4장 이상을 올렸다
- [ ] 다크 모드 화면이 한 장 있다 (지원하는 경우)

## 마무리

아이콘이 사람을 데려오는 입장권이라면, 스크린샷은 설치 버튼을 누르게 만드는 설득이에요. 지난 글에서 아이콘을 36px로 줄여봤다면, 이번에는 스크린샷을 **검색 결과 크기로 줄여서** 확인해보세요. 그 크기에서 읽히는 것만 사용자에게 전달돼요.
