신규 앱을 설치하자마자 가장 먼저 일어나는 일은, 우리의 1024×1024 공들인 아이콘이 **36×36 픽셀의 작은 사각형**으로 압축되어 사용자의 홈 화면 어딘가에 떨어지는 것입니다. 아이폰 15 Pro의 홈 화면에서 앱 아이콘은 60pt (약 180px @3x) 크기지만, *Spotlight 검색 결과*·*설정 앱 목록*·*통지 센터*에서는 29pt (약 36px @1x) 스케일로 노출됩니다.

문제는 사용자가 "이 앱을 열까 말까" 결정하는 그 짧은 순간이, 오히려 이 작은 스케일에서 더 많이 일어난다는 점이에요. 당신의 아이콘이 36px에서 **식별 가능한가**, **기억에 남는가**, **다른 아이콘과 구별되는가** — 이 세 가지 질문에 답할 수 없다면, 당신의 앱은 사용자의 홈 화면 2페이지로 밀려나 영영 열리지 않을지도 몰라요.

> "60pt에서 예뻤던 아이콘이 36px에서 뭉개져 사라집니다. 작게 그릴 수 있는 사람만 크게도 그릴 수 있어요."

## 36px이 왜 승부처인가

iOS는 당신의 1024×1024 원본으로부터 10개가 넘는 사이즈를 자동 생성합니다. 그중 사용자가 가장 자주 마주치는 작은 스케일은:

```
// iOS 아이콘 렌더 스케일 (사용 빈도 高 → 低)
홈 화면          180×180 (60pt @3x)
스포트라이트      120×120 (40pt @3x)
설정 리스트       87×87   (29pt @3x)
통지 센터         60×60   (20pt @3x)
앱스토어 썸네일   36×36   (리스트 뷰)
```

즉 당신의 아이콘은 사용자 눈에 띌 때 **36~60px 사이에 걸쳐 있을 확률이 가장 높아요**. 그런데 대부분의 디자이너는 1024px 캔버스에 예쁜 디테일을 넣고, 그게 축소될 때 어떻게 뭉개지는지는 체크하지 않습니다. 이게 *Figma 미리보기만 보고 끝내는 함정*이에요.

## 치트시트 — 36px에서 살아남는 7가지 원칙

### 1. 요소는 2개 이하
36px 캔버스엔 사실상 **상징 1개 + 배경**만 들어가요. 그 이상은 뭉개져요. 문자·로고타입·일러스트 중 *하나만* 고르세요. "회사 로고 + 제품 이름 + 서브 심볼" 다 넣으려는 유혹을 참아야 합니다.

### 2. 네거티브 스페이스 20% 이상
요소가 아이콘 경계에 닿으면 압축 과정에서 anti-aliasing 이 가장자리를 먹어버립니다. **중앙 65~70% 영역 안에** 핵심 상징을 가두세요. 애플 공식 가이드는 24pt 안전 영역을 1024pt 캔버스 안에서 확보하라고 명시해요.

### 3. 색은 2~3개
36px에서 사용자는 *색상 패턴*으로 아이콘을 인식해요 (형태 아님). 메인 1색 + 포인트 1색 + 배경 1색 정도가 한계. 그라데이션은 짧게 — 긴 그라데이션은 작은 스케일에서 '회색'으로 수렴합니다.

### 4. 선 두께는 3pt 이상 (@1x 기준)
1024 캔버스에서 1pt 가는 선은 36px에서는 0.035px — **사실상 사라져요**. 아이콘 안의 모든 선이 축소 후에도 보이려면 캔버스 기준 *최소 24~32pt*의 두께가 필요합니다. 가는 라인 아이콘이 유행이지만 iOS 아이콘엔 안 맞아요.

### 5. 글자는 1~2자 (영문) / 1자 (한글)
아이콘 안에 글자를 넣는다면 영문 2자, 한글 1자가 상한입니다. "AMU"는 36px에서 겨우 읽히고, "아무"는 흐려지고, "AMU 아무"는 완전히 사라져요. 한글은 획이 많아 영문보다 더 큰 글자 크기가 필요합니다.

### 6. 둥근 모서리는 iOS가 알아서 자른다
**절대 아이콘 PNG에 둥근 모서리를 그려 넣지 마세요**. iOS가 squircle (superellipse) 마스크를 자동으로 씌워요. 원본은 *정사각형 꽉 찬 디자인*으로 제출. 둥근 모서리 그려두면 iOS 마스크와 이중으로 겹쳐 모서리에 묘한 띠가 생깁니다.

### 7. 다크 모드 미리보기 필수
iOS 18부터 **다크/틴티드 아이콘**이 공식 지원됩니다. 밝은 배경에 흰색 상징을 쓴 아이콘은 다크 변형에서 완전히 뒤바뀌어 보여요. Figma 에서 다크 아트보드도 함께 디자인해두는 게 안전합니다.

## 인디메이커가 자주 하는 3가지 실수

**✗ Figma 400% 미리보기만 보고 export**
확대 상태에서 아름답던 디테일이 36px 축소 후 완전히 소실. 반드시 1배 실사이즈로 보고, iPhone 시뮬레이터 홈 화면에 실제로 깔아봐야 해요.
**✓ 대신:** Mac 미리보기 앱으로 1024→36 리사이즈 저장 후 바탕화면에서 25% 축소해서 보세요. 뭉개지는 요소가 바로 보여요.

**✗ "회사 이니셜 2자 + 제품 심볼 + 그라데이션 배경"**
정보 과다. 사용자는 아이콘에서 로고를 배우려 하지 않아요.
**✓ 대신:** 단색 배경 + 한글/영문 1자 또는 단순 심볼 1개. Toss, 카카오톡, Threads — 다 이 공식이에요.

**✗ 흰색 배경 + 밝은 포인트 색**
홈 화면 월페이퍼가 밝으면 완전히 사라집니다. 사용자는 "앱을 지웠나?" 당황해요.
**✓ 대신:** 포화도 높은 배경 + 대비 큰 전경. 흰색/검정 배경이라면 최소한 테두리가 필요해요.

## 테스트하는 방법 — 10분 자가진단

1. Figma 에서 1024×1024 아트보드를 **36×36 프레임**에 복제 → 미리보기 (Cmd+. 로 UI 숨김)
2. Mac 바탕화면에 36px PNG 저장 → 25% 축소해서 열기. 눈 가늘게 뜨고 봐도 식별 가능한가?
3. Xcode iPhone 시뮬레이터에 임시로 설치 → 홈 화면 2페이지 끝에 배치 → Spotlight 로 검색
4. 지인 3명에게 **5초 안에 "이게 뭐 하는 앱 같아?"** 질문. 못 맞추면 실패
5. 동일 카테고리 top 10 앱 아이콘 옆에 나란히 놓기. 묻히지 않는가?

### Export 전 최종 체크리스트

- ✓ 1024×1024 PNG 로 저장했고, 둥근 모서리는 그려 넣지 않았다
- ✓ 중앙 65~70% 안에 핵심 상징이 들어간다
- ✓ 36px 리사이즈 후에도 상징이 식별된다
- ✓ 선은 모두 24pt 이상 (1024 캔버스 기준)
- ✓ 색상 수는 2~3개 이내
- ✓ 다크 모드 변형도 함께 디자인했다
- ✓ 동일 카테고리 top 10과 나란히 놓았을 때 묻히지 않는다

## 마무리

작게 그릴 수 있는 사람만 크게도 그릴 수 있어요. 1024에서 아름다운 디테일보다, 36에서 분명한 실루엣이 사용자의 손가락을 당신 앱으로 이끕니다. *적게 넣을수록, 멀리 간다*는 디자인 격언이 아이콘에서는 특히 참입니다.
