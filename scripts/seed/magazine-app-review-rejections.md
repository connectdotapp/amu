앱을 다 만들고 심사에 올렸는데 반려 메일이 왔다면, 혼자만 겪는 일이 아니에요.

애플이 공개한 **2024년 앱스토어 투명성 보고서**에 따르면, 한 해 동안 심사한 앱 제출 건은 **7,771,599건**이었고 그중 **1,931,400건이 반려**됐어요. 대략 **4건 중 1건**이에요.

## 어떤 이유로 반려될까

보고서는 반려 사유를 심사 가이드라인의 큰 항목별로 나눠 보여줘요.

| 반려 사유 | 건수 |
|---|---|
| 성능 (Performance) | 1,235,471 |
| 법률 (Legal) | 445,696 |
| 디자인 (Design) | 378,300 |
| 비즈니스 (Business) | 209,845 |
| 안전 (Safety) | 116,105 |
| 기타 | 23,659 |

압도적으로 많은 건 **성능**이에요. 이름만 보면 "앱이 느려서"처럼 들리지만, 애플 심사 가이드라인에서 성능 항목은 **앱이 완성됐는지, 설명이 정확한지, 제대로 동작하는지**를 폭넓게 다뤄요. 대부분은 기술이 아니라 **준비 부족**에서 걸린다는 뜻이에요.

## 애플이 꼽은 자주 생기는 문제

애플은 심사 안내 페이지에 "흔한 문제 피하기" 목록을 따로 두고 있어요. 인디 메이커가 특히 자주 걸리는 것만 추리면 이래요.

1. **크래시와 버그**: 완성된 상태로만 제출하고, 최신 OS를 쓰는 실제 기기에서 테스트하세요.
2. **깨진 링크**: 앱 안의 모든 링크가 작동해야 하고, **고객 지원 연락처와 개인정보처리방침 링크는 모든 앱에 필수**예요.
3. **임시 콘텐츠**: "Lorem ipsum"이나 임시 이미지가 남아 있으면 승인되지 않아요.
4. **심사 정보 누락**: 로그인이 필요한 앱이라면 **심사용 데모 계정**을 꼭 넣어주세요.
5. **개인정보처리방침 부실**: 어떤 데이터를 어떻게 모으고, 어디에 쓰고, 얼마나 보관하고, 어떻게 삭제를 요청하는지까지 적어야 해요.
6. **권한 요청 설명 부족**: 카메라·위치 같은 권한을 요청할 때 **왜 필요한지** 설명 문구를 정확히 넣으세요.
7. **실제와 다른 스크린샷**: 스크린샷은 앱의 실제 기능을 보여줘야 해요.
8. **웹사이트를 감싼 앱**: 웹페이지를 앱 안에 그대로 띄운 것만으로는 좋은 앱으로 보지 않아요.
9. **거의 같은 앱 여러 개 제출**: 비슷한 앱은 하나로 합치세요.

## 반려는 끝이 아니에요

같은 보고서에서 반려된 제출 중 **295,109건은 문제를 고친 뒤 승인**됐어요. 반려 메일에는 어떤 가이드라인 조항에 걸렸는지 적혀 있으니, 그 조항을 읽고 고쳐서 다시 제출하면 돼요.

심사 속도도 생각보다 빨라요. 애플은 제출 건의 **50% 이상을 24시간 안에, 90%를 48시간 안에** 심사한다고 안내해요. 한 번 반려돼도 일정이 크게 밀리지는 않아요.

## 제출 전 체크리스트

- [ ] 최신 OS 실제 기기에서 처음부터 끝까지 써봤다
- [ ] 임시 문구·임시 이미지가 하나도 없다
- [ ] 앱 안의 모든 링크가 열린다
- [ ] 고객 지원 연락처와 개인정보처리방침 링크가 있다
- [ ] 로그인이 필요하면 심사용 데모 계정을 적었다
- [ ] 권한 요청마다 이유 문구를 넣었다
- [ ] 스크린샷이 실제 화면과 같다

## 마무리

4건 중 1건이 반려된다는 건, 반대로 말하면 **준비만 잘해도 앞서 나갈 수 있다**는 뜻이에요. 반려 사유 대부분이 기술보다 꼼꼼함의 문제거든요. 제출 버튼을 누르기 전에 체크리스트 한 번만 훑어보세요.
